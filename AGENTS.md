# Instrucciones del SIGA

- Leer `docs/ESTADO.md` al iniciar y actualizarlo después de cada subetapa.
- Consultar `GUIA_CONSTRUCCION_SIGA_CODEX.txt`, `docs/DECISIONES.md` y el backlog antes de ampliar el alcance.
- Conservar TypeScript, React/Vite, NestJS, PostgreSQL y el monorepositorio npm. Prisma se incorpora en E02.
- Implementar una etapa a la vez. No reiniciar ni sustituir código útil en una sesión nueva.
- Mantener IDs RF/RN/RNF y términos de dominio en español; nombres de archivos sin tildes.
- Usar datos ficticios. No publicar secretos, inventar resultados ni marcar pruebas no ejecutadas como aprobadas.
- La API debe autorizar por rol y recurso. Matrícula transaccional y cálculos académicos precisos son obligatorios en sus etapas.
- Las propuestas académicas no equivalen a reglas aprobadas. Mantenerlas configurables y registrar decisiones.
- Preservar cambios ajenos. No borrar volúmenes, hacer resets destructivos ni publicar sin autorización.
- Ejecutar las verificaciones pertinentes y documentar limitaciones; no escribir tests que solo reflejen la implementación.
- No hacer commits salvo instrucción del usuario. Guardar cambios y un punto de continuidad es suficiente.
- Comandos y estado verificado: `README.md` y `docs/ESTADO.md`.
