## Constancias ante interrupción y respuesta perdida (AC-09)

La prueba de integración de cobertura `certificados.integration.spec.ts` provoca la pérdida de la conexión HTTP después de que devuelve la emisión y verifica listado, PDF, hash, una auditoría y rechazo de recuperación duplicada. Su fixture utiliza una transacción externa: no acredita por sí solo un commit durable. Por separado, `scripts/test-certificados-crash.mjs` ejecutado con otra conexión y esquema temporal mata procesos antes y después del commit. Antes deja pendiente recuperable con una sola auditoría; después conserva emisión, hash y descarga y rechaza el reintento. [Resultado del proceso interrumpido](evidencias/constancias-interrupcion-20261110.json). Además se ejecutó una prueba nueva con una aplicación y una conexión observadora independientes: destruye el socket HTTP tras la emisión y comprueba desde la segunda conexión el certificado confirmado, una sola auditoría, hash de descarga y rechazo de recuperación duplicada. Se ejecutó dentro de las 140 pruebas de cobertura; el esquema de prueba se elimina al terminar.

La comprobación general final pasó: lint, tipos, 7 suites y 46 pruebas API, 13 archivos y 40 pruebas web y compilaciones. [Registro](evidencias/check-20261110.log).

## Pendientes para el cierre

Siguen requiriendo trabajo técnico o evidencias: matriz de autorización y casos positivos AC-06; trazabilidad completa por programa AC-07; inventario y pruebas de listas AC-08; ensayo de timeout/recuperación AC-10; candidato final y pruebas vinculadas AC-11; manifiesto final de entrega AC-12; actualizar los documentos académicos de 2026-11-09 con resultados nuevos sin alterar la evidencia histórica, AC-14/15/16; tareas críticas al 200 % AC-04 y el caso tardío completo AC-05. Una publicación remota de CI depende de contar con un repositorio autorizado.

Además, ninguna prueba automatizada sustituye responsables reales de respaldos, piloto y capacitación con participantes, evaluación, evidencia metodológica auténtica y aceptación firmada. No se declara el proyecto 100 % concluido ni se agregan módulos fuera del alcance.

## Reproducción y seguridad de los datos

Ejecutar `npm run test:coverage` y `npm run test:e2e -- --workers=1` con `TEST_DATABASE_URL` apuntando a PostgreSQL de prueba diferente de la base de desarrollo, siguiendo la configuración local del proyecto. Los runners crean y eliminan esquemas propios. `scripts/test-backup-restore-local.mjs --packaged` utiliza Docker y recursos temporales propios; requiere imágenes empaquetadas y sus precondiciones. El resultado de recuperación citado empleó imágenes preexistentes identificadas en el JSON. No debe dirigirse ninguna prueba destructiva a datos de personas reales.

La sesión no tuvo disponible la herramienta de subagentes; este avance se ejecutó secuencialmente. La falta de esa herramienta no representa una aprobación ni una prueba adicional.
