# PB-13: proxy HTTP y cookie local

Fecha: 6 de noviembre de 2026, America/Mexico_City. Ejecutor: subagente de entrega. Las imagenes ensayadas fueron API `sha256:71f6f28f370bbddcaac7f53befdf96c81630b3c9a5424e491cc40cc02573f6f7`, web `sha256:500b140d977c4b9e11dbe9164be98f1a5cc393b51055af7f1cfcdc90b1542664` y migraciones `sha256:453bef752210991049c4384ee04aaa39bb48a90c578d18fb5576a03fea2c16a4`. PostgreSQL, red, contenedores, usuario y credenciales fueron ficticios y aislados; los recursos propios se retiraron.

El primer ensayo encontro `X-Content-Type-Options: nosniff, nosniff` en respuestas de la API porque Nginx y Helmet la anadian. Se oculto la copia procedente del upstream en la ubicacion `/api/` para conservar una cabecera `nosniff` emitida por Nginx. Se reconstruyo la imagen web y se repitio el ensayo.

Resultado **PASO**, `node scripts/test-proxy-local.mjs` con `SIGA_PROXY_API_IMAGE`, `SIGA_PROXY_WEB_IMAGE` y `SIGA_PROXY_MIGRATE_IMAGE` apuntando a las tres imagenes: pagina 200 y recurso estatico inexistente 404 con una cabecera `nosniff`; API `health` 200 y ruta inexistente 404 con una cabecera `nosniff`; login 200, perfil 200, logout 204 y sesion anterior 401. Se verificaron `HttpOnly`, `SameSite=Strict`, `Path=/` y ausencia de `Secure` para HTTP local; no se registro la cookie ni la contrasena.

Esto prueba el camino local HTTP del conjunto de imagenes. No acredita HTTPS publico, proxy remoto, accesibilidad completa ni funcionamiento ante cualquier timeout. En despliegue HTTPS futuro la configuracion requiere `COOKIE_SECURE=true`. Cambios posteriores de imagenes o configuracion requieren repetir lo afectado.
