# SIGA: ampliación funcional integrada (12/11/2026)

La ampliación se incorporó **sin sustituir** los módulos previos de autenticación, catálogos, personas, oferta, matrícula, calificaciones, reportes y constancias. El trabajo incluye backend, contratos, pantallas por rol y una migración aditiva de PostgreSQL. Es una **implementación funcional de desarrollo**, pendiente de validación de integración con PostgreSQL, pruebas E2E de los nuevos flujos y aprobación de reglas académicas antes de uso institucional.

## Despliegue / conservación de datos

1. **Respaldar PostgreSQL antes de desplegar** y conservar una copia íntegra del proyecto anterior. No aplicar un reset de la base.
2. Utilizar la versión de Node y npm declarada en `package.json`; desde raíz ejecutar `npm ci`, configurar `.env` desde `.env.example` con valores propios, `npm run db:generate`, `npm run db:migrate`, `npm run build` y `npm run dev` (o los scripts Docker del README original). Si se distribuye el código por separado del ZIP original, **conservar `apps/api/assets/fonts/` del proyecto original** para generar certificados PDF.
3. La migración nueva es `apps/api/prisma/migrations/20261112000000_ampliacion_academica/migration.sql`. Agrega tablas para horarios, evaluaciones, notas parciales, espera, notificaciones, asistencia y recuperación, además del tipo de certificado `CONCLUSION` y la configuración de cancelación por periodo. No elimina tablas ni columnas anteriores.
4. Configurar expresamente horarios de los grupos y la política de cancelación por periodo. Si aún no hay horarios, la matrícula mantiene compatibilidad con la oferta histórica; si un grupo no tiene horario, no puede detectarse un choque de ese grupo.
5. Configurar las evaluaciones antes de introducir la primera nota final en un grupo; sumar ponderaciones a 100 % para activar la nota final calculada.
6. Conservar `*.env` y archivos `.local` exclusivamente en el entorno privado. El paquete de entrega no contiene secretos ni respaldos reales.

## Pruebas efectuadas en esta ampliación

- Validación del esquema Prisma: **correcto**.
- TypeScript backend y frontend: **correcto**.
- ESLint: **correcto**.
- Build de NestJS y build de React/Vite: **correctos**.
- Tests unitarios API: **8 suites, 48 pruebas correctas**.
- Tests unitarios frontend: **13 archivos, 40 pruebas correctas**; se actualizó la regresión del mapa curricular para reflejar el cambio de comportamiento esperado.

**No se ejecutaron** migraciones sobre PostgreSQL en vivo, tests de integración de los nuevos endpoints, pruebas E2E, pruebas de concurrencia multiinstancia ni auditoría de seguridad independiente. No se afirma que la ampliación esté certificada para producción. Una política académica provisional debe ser validada por la universidad.

## Limitaciones identificadas y siguientes verificaciones

- Debe parametrizarse el requisito de **créditos y materias obligatorias** para programas con asignaturas optativas; el criterio actual de conclusión exige todas las asignaturas del plan, lo que puede bloquear una conclusión legítima si el catálogo contiene electivas no obligatorias.
- Las alertas usan umbrales provisionales; adaptar a escala y normativa de cada programa. El promedio de alertas no reemplaza el cálculo oficial de promedio por créditos en el módulo existente.
- La reserva de espera no vence automáticamente: depende de que siga abierto el periodo y de que el alumno confirme. Para producción conviene agregar expiración, revalidación periódica y escalamiento de eventos/colas compartidas entre instancias.
- El primer listado administrativo de estadísticas tiene límite de 40 grupos; se requiere paginación o agregación para informes institucionales grandes.
- Probar la transacción que libera un cupo, corrección de evaluaciones y generación de certificados con un PostgreSQL de pruebas, usando varios estudiantes al mismo tiempo; verificar migración con una copia anonimizada del esquema existente.
- Registrar en Scrum historias de usuario, criterios de aceptación, pruebas TDD, Review y Retrospective de la ampliación. La implementación de código no equivale por sí sola a la evidencia de ceremonias Scrum.
